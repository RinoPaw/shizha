## 1 文档目的与适用范围

本规范用于指导反诈智能体项目中的数据收集、整理、脱敏、标注、审核和引用。目标是形成一套可用于知识库构建、RAG 检索、风险识别、人工复核和后续项目合作论证的数据基础。

本规范不追求一开始建立复杂数据库，而是先构建四类基础数据：案例库、字典库、处置方案库、相关法规库。

| 数据类型 | 核心问题 | 主要用途 |
|----------|----------|----------|
| 案例库 | 发生了什么？ | 记录具体诈骗、疑似诈骗、诈骗前兆、易混淆场景。 |
| 字典库 | 用什么标准词描述？ | 统一入口渠道、冒充身份、关键手法、目标资产等枚举值。 |
| 处置方案库 | 用户遇到后怎么办？ | 按用户已发生行为给出行动建议。 |
| 相关法规库 | 依据是什么？ | 支撑性质判断、隐私保护、脱敏、数据安全和处置建议。 |

> **边界说明：** 本规范用于数据采集与智能体知识库设计，不用于替代公安机关、司法机关、金融机构或平台方的案件认定、执法处置和法律判断。

## 2 四类数据体系

四类数据之间形成闭环：案例库负责事实，字典库负责标准化，处置方案库负责行动建议，相关法规库负责依据。

| 关系 | 说明 |
|------|------|
| 案例库 → 字典库 | 案例库中的入口渠道、冒充身份、关键手法、目标资产、风险等级等字段引用字典库标准词。 |
| 案例库 → 处置方案库 | 案例按用户已发生行为和风险等级关联相应处置方案编号。 |
| 案例库 → 相关法规库 | 案例性质判断、脱敏要求、处置建议可关联法规依据编号。 |
| 处置方案库 → 相关法规库 | 涉及报警、止付、冻结、个人信息保护等建议时，应关联法规或官方依据。 |

## 3 正式合作场景下的额外要求

如项目进入正式合作或外部单位共建场景，数据规范需要从“项目内部可用”提升到“可审查、可复核、可交接”的标准。建议至少增加以下要求。

### 3.1 数据边界

- 优先使用公开发布资料、法律法规、官方宣传材料、公开数据集、平台公告和权威媒体报道。
- 不主动收集真实报案材料、未公开案件材料、真实受害人身份信息、真实涉案账号、真实涉案网址原文。
- 如合作单位提供内部材料，应由合作单位明确使用范围、脱敏方式、存储方式、访问权限和销毁要求。
- 个人经历可作为风险场景线索，但不能直接作为正式权威依据。

### 3.2 数据安全与权限

- 建立数据访问权限：采集者、标注者、审核者、管理员分级授权。
- 建立版本记录：每次字段变更、来源补充、脱敏修改、删除请求应有记录。
- 建立来源留痕：来源名称、链接、发布日期、采集日期、采集人、审核状态应可追溯。
- 建立发布审查：对外展示或接入智能体前，应进行敏感信息检查、法律依据检查和错误分类检查。

### 3.3 表述风险提示

应避免在项目文档中使用“已确认违法犯罪”“可精准识别嫌疑人”等表述。更稳妥的表达是“风险识别”“疑似场景研判”“公众防范提示”“数据采集与标注参考”。

## 4 基本原则

### 4.1 不以 AI 判断作为最终依据

AI 可以辅助归纳字段、提取风险信号、生成初步标注，但不能替代来源材料、人工审核、法律审查和合作单位确认。

### 4.2 不直接把官方宣传分类当作严谨主分类

公安部刑侦局、国家反诈中心《2025版防范电信网络诈骗宣传手册》中的 10 类高发类型适合用于官方宣传参考类别，但不宜作为唯一分类标准。现实诈骗往往跨入口渠道、冒充身份、关键手法和目标资产。

### 4.3 不设置案例簇

本项目采用“一案一条记录，重复报道合并，相似事件分开”的方式。不同真实事件分别建记录；同一事件被多个网站报道时合并为一条，并在来源字段中记录多个来源。

### 4.4 必须脱敏与最小化采集

不得保存真实姓名、身份证号、银行卡号、手机号、社交账号、详细住址、涉案网址原文、未脱敏聊天记录等敏感信息。只保留用于风险识别、案例归纳和防范建议的必要信息。

## 5 案例库规范

案例库用于记录具体诈骗、疑似诈骗、诈骗前兆、账号安全风险、个人信息泄露风险或易混淆场景。

### 5.1 核心字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 案例编号 | 文本 | 是 | 唯一编号，如 FZ-001 |
| 案例标题 | 文本 | 是 | 一句话概括案例 |
| 场景简述 | 长文本 | 是 | 100-200 字描述发生了什么 |
| 性质判断 | 单选枚举 | 是 | 确认诈骗、疑似诈骗、诈骗前兆等 |
| 判断理由 | 长文本 | 是 | 为什么这样判断 |
| 入口渠道 | 多选枚举 | 是 | 电话、短信、Steam、Telegram、搜索引擎等 |
| 冒充身份 | 多选枚举 | 是 | 冒充客服、官方、银行、公检法等 |
| 虚假认知 | 多选枚举 | 是 | 用户被诱导相信什么 |
| 关键手法 | 多选枚举 | 是 | 钓鱼链接、仿冒官网、索要验证码等 |
| 目标资产 | 多选枚举 | 是 | 钱、账号、验证码、个人信息等 |
| 诈骗阶段 | 多选枚举 | 是 | 接触引流、诱导操作、资产获取等 |
| 风险信号 | 长文本/多标签 | 是 | 本案例触发的危险点 |
| 风险等级 | 单选枚举 | 是 | 低、中、高、极高、无法判断 |

### 5.2 来源与管理字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 涉及平台 | 文本/多选 | 建议 | Steam、Telegram、Bing、微信等 |
| 受害群体 | 文本/枚举 | 建议 | 学生、老人、游戏玩家、网购用户等 |
| 是否造成损失 | 单选枚举 | 是 | 是、否、未知、未造成但存在风险 |
| 损失类型 | 多选枚举 | 建议 | 金钱损失、账号被盗、个人信息泄露等 |
| 官方宣传参考类别 | 多选枚举 | 建议 | 对应 2025 版手册宣传类别 |
| CCL2023 参考类别 | 单选/多选 | 可选 | 对应公开数据集分类 |
| 自定义细分类 | 文本 | 建议 | 如“仿冒官网”“免费保险钓鱼” |
| 标签 | 字符串数组 | 建议 | 例如 `["免费保险", "短信链接"]` |
| 防范建议 | 长文本 | 是 | 没被骗前应该怎么避免 |
| 应急方案编号 | 文本 | 建议 | 关联处置方案库 |
| 法规依据编号 | 字符串数组 | 建议 | 关联相关法规库 |
| 来源名称 | 文本 | 是 | 资料来源名称 |
| 来源类型 | 单选枚举 | 是 | 官方、论文、数据集、媒体、个人经历等 |
| 来源链接 | URL 数组 | 建议 | 可追溯链接 |
| 发布日期 | 日期 | 建议 | 来源发布时间 |
| 采集日期 | 日期 | 是 | 整理数据的日期 |
| 是否脱敏 | 单选枚举 | 是 | 是、否、不涉及、待处理 |
| 备注 | 长文本 | 可选 | 不确定内容、相似案例说明等 |

| 字段 | 枚举值 |

| CCL2023 参考类别 | 刷单返利类；冒充电商物流客服类；虚假网络投资理财类；贷款、代办信用卡类；虚假征信类；虚假购物、服务类；冒充公检法及政府机关类；冒充领导、熟人类；网络游戏产品虚假交易类；网络婚恋、交友类；冒充军警购物类；网黑案件；无法对应 |

### 5.4 风险等级建议

| 等级 | 判断标准 |
|------|----------|
| 低 | 只有一般可疑信息，未涉及敏感操作。 |
| 中 | 出现陌生链接、陌生客服、可疑福利、非官方渠道。 |
| 高 | 要求输入账号密码、身份证、银行卡、验证码，或下载陌生 App。 |
| 极高 | 要求转账、屏幕共享、输入验证码、转移资产、缴纳保证金/解冻费。 |
| 无法判断 | 信息不足，无法形成可靠判断。 |

### 5.5 相似案例处理规则

| 情况 | 处理 |
|------|------|
| 不同真实事件，但套路相似 | 分别建立独立案例记录。 |
| 同一事件被多个网站报道 | 合并为一条案例，来源名称和来源链接可填多个。 |
| 同一公安通报被复制转载 | 不重复建案例，只补充来源或备注。 |
| 相似但关键手法、目标资产或处置方案不同 | 新建案例。 |

## 6 字典库规范

字典库用于统一案例库中的标准词，避免“假官网、钓鱼网站、仿冒网页”等同义词混用导致统计混乱。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 字典编号 | 文本 | 是 | 如 DIC-001 |
| 字典类型 | 单选 | 是 | 入口渠道、关键手法、风险信号等 |
| 标准名称 | 文本 | 是 | 统一使用的标准词 |
| 别名/近义词 | 文本 | 建议 | 常见说法 |
| 定义说明 | 长文本 | 是 | 该词是什么意思 |
| 适用条件 | 长文本 | 建议 | 什么情况下使用 |
| 不适用情况 | 长文本 | 建议 | 什么情况下不要使用 |
| 默认风险等级 | 单选 | 可选 | 低/中/高/极高 |
| 示例 | 长文本 | 建议 | 一个简单例子 |
| 是否启用 | 单选 | 是 | 是/否 |
| 备注 | 长文本 | 可选 | 其他说明 |

| 字典类型 | 标准名称 | 别名/近义词 | 定义说明 | 默认风险等级 |
|----------|----------|--------------|----------|--------------|
| 关键手法 | 仿冒官网 | 假官网；钓鱼网站；仿冒网页 | 通过伪装成官方网站诱导用户登录、付款或填写信息。 | 高 |
| 风险信号 | 索要验证码 | 要验证码；输入验证码；提供验证码 | 对方要求用户提供短信、登录或支付验证码。 | 极高 |
| 入口渠道 | 搜索引擎 | Bing；百度；Google | 用户通过搜索结果进入风险页面。 | 中 |
| 冒充身份 | 冒充平台官方 | 冒充管理员；冒充安全中心 | 伪装成平台官方人员联系用户。 | 高 |

## 7 处置方案库规范

处置方案库记录用户遇到风险后的行动建议。案例库记录“发生了什么”，处置方案库记录“现在怎么办”。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 处置方案编号 | 文本 | 是 | 如 CZ-001 |
| 适用场景 | 文本 | 是 | 如“已点击陌生链接” |
| 用户已发生行为 | 单选/多选 | 是 | 已点击、已填写、已转账等 |
| 风险等级 | 单选 | 是 | 低/中/高/极高 |
| 立即停止行为 | 长文本 | 是 | 立刻不要继续做什么 |
| 第一步处置 | 长文本 | 是 | 最先该做什么 |
| 第二步处置 | 长文本 | 建议 | 接下来该做什么 |
| 证据保存 | 长文本 | 建议 | 保存哪些材料 |
| 账号/资金处理 | 长文本 | 建议 | 改密、冻结、止付等 |
| 设备处理 | 长文本 | 可选 | 卸载 App、检查权限等 |
| 报警/举报建议 | 长文本 | 建议 | 是否报警、举报到哪里 |
| 官方核验方式 | 长文本 | 建议 | 去哪里核实 |
| 不建议行为 | 长文本 | 是 | 明确不要做什么 |
| 适用案例类型 | 文本/多选 | 建议 | 可关联案例类型 |
| 相关法规编号 | 文本 | 建议 | 关联法规库 |
| 来源名称 | 文本 | 是 | 处置建议来源 |
| 来源链接 | URL | 建议 | 可追溯链接 |
| 备注 | 长文本 | 可选 | 其他说明 |

### 7.1 处置方案类型建议

- 只是收到短信/私信/电话
- 已点击陌生链接但未填写
- 已填写账号密码
- 已填写身份证/银行卡信息
- 已提供验证码
- 已转账
- 已下载陌生 App
- 已开启屏幕共享
- 账号已被盗
- 设备疑似被控制

## 8 相关法规库规范

## 9 易混淆情况处理规则

| 易混淆情况 | 建议判断 |
|------------|----------|
| 只是反复推销，没有要求填写敏感信息或付款 | 骚扰营销 |
| 出现短信链接、身份证、银行卡、验证码、付款等动作 | 诈骗前兆/风险信号 |
| 商家确实提供商品/服务，但夸大效果 | 虚假宣传/消费欺诈 |
| 从一开始没有真实商品，收款后拉黑 | 疑似诈骗/确认诈骗 |
| 发货慢、售后差、商品不满意 | 普通消费纠纷 |
| 发现假官网、假链接，但未输入信息 | 诈骗前兆/风险信号 |
| 已输入账号密码、银行卡、验证码 | 疑似诈骗 |
| 已造成资金损失或账号被盗 | 确认诈骗 |

## 10 数据采集流程与质量控制

### 10.1 采集来源优先级

1. 法律法规
2. 公安部、国家反诈中心等官方资料
3. 法院/检察院典型案例
4. 公开数据集
5. 学术论文
6. 平台公告
7. 权威媒体报道
8. 个人经历

### 10.2 采集步骤

1. 确定来源并记录来源信息。
2. 提取案例标题、场景简述、风险信号和来源。
3. 删除或替换敏感个人信息。
4. 使用字典库标准词标注入口渠道、冒充身份、关键手法、目标资产等。
5. 判断性质和风险等级，并写明判断理由。
6. 关联应急方案编号和法规依据编号。
7. 由第二人复核关键字段，尤其是性质判断、风险等级、脱敏和来源。

### 10.3 质量检查清单

- 是否有来源？
- 是否已脱敏？
- 是否填写判断理由？
- 是否把骚扰营销误标为诈骗？
- 是否把消费纠纷误标为诈骗？
- 是否填写关键手法和目标资产？
- 是否填写风险等级？
- 是否能追溯到来源？
- 是否需要补充处置方案？
- 是否需要补充法规依据？
- 是否存在可能对外泄露的敏感链接或账号？

### 10.4 数据质量等级

| 等级 | 标准 |
|------|------|
| A | 法律法规、官方资料、法院/检察院案例，字段完整，已脱敏。 |
| B | 公开数据集、论文、平台公告，字段较完整，来源可信。 |
| C | 权威媒体报道，有明确案例细节，已脱敏。 |
| D | 个人经历或普通网络资料，待核验。 |
| E | 来源不明或无法复核，不建议进入正式库。 |

## 12 分类依据与字段映射

本项目的数据分类不直接照搬单一诈骗名称，而采用多维标注框架。依据包括官方反诈宣传分类、公开案件分类数据集、钓鱼攻击研究、犯罪脚本分析、日常活动理论、现代诈骗理论以及 AI 知识库可追溯要求。

| 字段/模块 | 主要依据 | 说明 |
|-----------|----------|------|
| 性质判断 | 《反电信网络诈骗法》 | 判断是否接近电信网络诈骗。 |
| 是否脱敏 | 《个人信息保护法》；CCL2023 | 防止保存敏感个人信息。 |
| 官方宣传参考类别 | 2025 版反诈手册 | 保留官方宣传口径，不作为唯一主分类。 |
| CCL2023 参考类别 | CCL2023 数据集 | 参考案件分类和脱敏方式。 |
| 入口渠道 | Alabdan 2020；Phishing taxonomy | 电话、短信、网页、平台私信等入口。 |
| 冒充身份 | Alkhalil 2021；社会工程研究 | 记录对方伪装成谁。 |
| 虚假认知 | 社会工程/钓鱼攻击研究 | 记录用户被诱导相信什么。 |
| 关键手法 | Phishing taxonomy | 钓鱼链接、仿冒官网、屏幕共享等。 |
| 目标资产 | Harding et al. 2025 | 不只包括钱，也包括账号、数据、权限。 |
| 诈骗阶段 | Crime script analysis | 拆解接触、诱导、收割、二次压榨等过程。 |
| 脆弱情境 | Routine Activity Theory | 分析为什么这个场景容易被骗。 |
| 来源字段 | RAG / NIST AI 风险管理资料 | 支撑智能体回答可追溯、可复核。 |

## 附录：填写格式约定

- 多选字段统一使用 JSON 字符串数组，例如：`["电话", "短信"]`。
- 日期建议使用 YYYY-MM-DD 格式。
- 来源链接如涉及可疑链接或涉案链接，不保留原文，可写“\[链接已脱敏\]”。
- 判断理由必须说明具体触发的风险信号，不写“感觉像诈骗”。
- 防范建议应具体可执行，不写空泛口号。
- 如进入正式合作场景，可根据合作单位要求另行添加审核人、审核日期、审核意见等管理字段。
